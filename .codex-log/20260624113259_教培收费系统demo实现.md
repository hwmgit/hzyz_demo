# 需求分析

用户需要在空目录中创建一个教培收费系统 Demo，用 H5 页面和假数据点击交互演示收费闭环。客户核心需求包括：后台导入学生、配置收费项目、监控缴费状态；家长访问部署后的 URL，输入学生姓名和身份证号完成身份核验，查看待缴项目并模拟聚合支付。

本次用户补充约束：

- 不需要中英双语切换。
- 不需要拉起 Chrome 截图验证。
- Demo 内不做扫码模拟入口；部署后用户按 URL 自行生成二维码。
- 后台导入学生与家长端输入数据必须一致校验，例如导入学生A和身份证号码123后，家长端必须输入学生A和123才通过。

# 方案设计

采用纯静态中文 H5 单页方案：

  - `index.html` 内置 HTML、CSS、JS。
  - 使用统一前端状态 `state.students` 存放学生数据。
- 后台导入/新增学生写入同一数据池。
- 家长端 `verifyStudent()` 从同一数据池精确匹配姓名和身份证号。
- 支付成功后 `payCurrentStudent()` 更新 `state.payments`，并重新渲染家长端和后台。
- 预埋 Umami 统计结构，但本地和未配置生产信息时不发送统计。

# 任务规划

1. 创建 `demo需求分析.md` 和 `DESIGN.md`。

# 审查分析

当前实现符合用户修订范围：

- 未实现中英切换。
