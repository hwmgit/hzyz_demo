# 需求分析

用户确认将“学生当前关联项目”和“已支付结果”拆开处理：

- 学生已支付项目不允许被后续关联操作取消。
- 后续新增关联项目不能继续沿用已支付状态，应进入待补缴。
- 后台改金额或禁用项目不能回写历史已支付金额。

# 方案设计

- 为每个已支付学生引入 `paidSnapshot`，冻结支付时的项目名称、周期和金额。
- 学生 `feeIds` 继续表示当前关联项目集合，但后台移除/清空时必须保留已支付快照中的项目。
- 家长端与后台统一按三种状态展示：待支付、已支付、已支付后新增待补缴。

# 代码实现

- `index.html`：支付成功时不再只写 `status=paid`，而是写入 `paidSnapshot`。
- `index.html`：家长端详情按“已支付项目 + 新增待补缴项目”分区展示，待缴金额仅统计未支付项目。
- `admin.html`：后台关联、移除、清空逻辑保留已支付项目，避免误取消。
- `admin.html`：状态监控与 KPI 改为基于支付快照计算，不再直接依赖当前关联项目。
- `AGENTS.md`：补充支付快照与已支付冻结规则。
